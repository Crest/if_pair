# PLAN P4c design study, 2026-10-20: three designs for sharing a saturated
# worker's CPU, run through tests/t_34_interactive.sh on the three machines.
#   share    the kwq branch's share limit (cap_permille knob), here at 500
#            and 1000, rtt mode only (its other modes are in
#            samples/t34_sweep_2026-10-20_three_machines.txt)
#   tickfair branch kwq-cap-tickfair: no tuning; class priority for half of
#            each millisecond, idle priority (PRI_MIN_IDLE) for the rest,
#            one voluntary switch, ULE preempts and re-picks, the deadline
#            callout raises; alone the worker runs through
#   ule      branch kwq-cap-ule: no callout, no share; round-end yield to
#            every thread ULE scores interactive (114) and a yield at
#            PRI_USER when ULE ends the worker's slice (TDF_SLICEEND)
# Modes as in t34_sweep: timer / spin / exec / rtt (the flow's own TCP RTT
# from iperf3 -J beside the spinner, us) / unpinned.  "ratio" is the knob
# value the harness wrote; for ule the limit is off (1000).
# The ule design's slice yields were 0 on the guest (26 k wakeups in the
# window): sched_wakeup() resets ts_slice, so a worker that sleeps between
# bursts never reaches a slice end; on lab the saturated worker (busy 0.9-1.0,
# no sleeps) did reach it and shared at ULE's slice granularity.
