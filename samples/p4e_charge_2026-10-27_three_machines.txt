# Stages on one boot per machine: W0 (kwq ead65d1) and the tick build (kwq-wake-tick) at
# kern.kwq.net.tick_us=50 under kern.kwq.net.charge 0 wall (CHW), 1 cpu (CHC), 2 split (CHS),
# 3 hybrid (CHH); tests twoq coloc rwlock preempt spin timer udp_load; two repetitions, medians.
# Competitors: burst = a 1 kHz timeshare thread with 400 us of work per wake pinned to W (it can
# preempt the worker only while the share limit has demoted it); intr = kwq_test's intr_load,
# 20 us of interrupt context every 100 us on W.  Change in brackets against CHW, so that the
# column isolates the charge mode from the tick.
# The second battery (p4e_charge2_*) ran the split mode with its pass-begin clock still wrong
# (b323af4: the share limit got the CPU clock at pass begin and wall at pass end, so its period
# rolled over every pass and never engaged: spinner starved, 22 ms timer lateness); its CHS
# column is that bug.  The third battery (p4e_charge3_*) re-ran CHW and CHS with the fix on the
# same boot; "CHS (fixed)" below is that run against its own CHW.  Raw rows: p4e_charge2_{burst,
# intr}_{lab,a07,guest}, p4e_charge3_{burst,intr}_{lab,a07}, p4e_charge4_{intr,burst}_guest.
# The guest is GENERIC-DEBUG under bhyve: direction only, and a vCPU's steal time is CPU time to
# the guest's thread clock.
