kwq.ko implementation plan
==========================

Written 2026-09-23, terminology per GLOSSARY.md.  Companion to KWQ.md
(design, this directory),
../POOLS.md (cross-OS survey) and ../DISPATCH.md (libdispatch study).
Same conventions as ../CHOPPER.txt: phases with status markers, exit
criteria per phase, measurements recorded in ../NOTES.md and ../samples/.
Target: FreeBSD 15.x GENERIC, amd64 and arm64, built as an out-of-tree
module in this directory, graduating to sys/kern once if_pair, epair and
wg run on it.

Layout
------

All kwq code lives under kwq/ in this repository, separate from the
if_pair module in the parent directory:

  kwq/README.md            map of this directory
  kwq/KWQ.md               design (this plan's companion)
  kwq/PLAN.txt             this file
  kwq/Makefile             SUBDIR= kwq kwq_test (bsd.subdir.mk)
  kwq/kwq/                 kwq.ko: the service
    kwq.h                  public KPI (KWQ.md S2), kwq_item, kwq_params
    kwq_internal.h         struct kwq, struct kwq_cpu, struct kwq_worker
    kwq.c                  create/activate/enqueue/drain/destroy, sysctl
    kwq_worker.c           workers, DRR drain loop, yield, monitor
    kwq_sdt.c              SDT provider + probe definitions
    kwq_ddb.c              show kwq
    kwq.d                  D translator (installed to /usr/lib/dtrace)
    Makefile               bsd.kmod.mk, KMOD=kwq
  kwq/kwq_test/            kwq_test.ko: synthetic clients driven by sysctl
    kwq_test.c, Makefile
  kwq/tests/               ATF sh tests (Kyuafile) + kwq_lib.sh
  kwq/examples/            compilable examples (build against ../kwq/kwq.h)
    deferred.c             minimal deferred-work client
    scatter.c              BULK fan-out with completion callback
    pair_client.c          the if_pair conversion, as a diff description
  kwq/man/                 kwq.9, dtrace_kwq.4 (mdoc, mandoc -T lint clean)

The if_pair conversion (P4) adds MODULE_DEPEND(if_pair, kwq, 1, 1, 1) to
../Makefile and includes ../kwq/kwq/kwq.h; until then the two trees build
independently.

[TODO] P0  Skeleton and lifecycle (2-3 days)
    Files: kwq/kwq/{kwq.h,kwq_internal.h,kwq.c,kwq_worker.c,Makefile}.
    - Classes NET and BULK only; BLOCKING stubbed (kwq_create returns
      NULL for it, asserted under INVARIANTS).
    - Workers: one per (class, online CPU), created at module load in a
      SYSINIT(SI_SUB_TASKQ); each worker binds ITSELF after waiting for
      smp_started (GELI pattern, g_eli.c:668-681); names kwq_net/N,
      kwq_bulk/N; priorities PI_NET / PI_SOFT.
    - Queue objects: kwq_create(name, class, flags, params, fn, ctx)
      allocates struct kwq (read-mostly header in its own cache line,
      runtime-written fields at the end) + one struct kwq_cpu per CPU
      via malloc_domainset_aligned(CACHE_LINE_SIZE, the CPU's domain),
      pointers in a read-mostly array; kwq_cpu layout per KWQ.md S17:
      line 0 = mtx + list + depth + state + empty_since + rejected,
      consumer-private line(s) = deficit, ring link, plain uint64
      counters; whole struct __aligned(CACHE_LINE_SIZE) with a CTASSERT
      that the shared part fits one line.  Registers
      kern.kwq.<class>.<name>; KWQ_F_INACTIVE and kwq_activate();
      KWQ_F_SPIN selects MTX_SPIN.
    - Workers: struct kwq_worker per (class, CPU), aligned and allocated
      on the CPU's domain; wait channel is a field of it; INVARIANTS
      check at load that no two workers of a class hash to the same
      sleepqueue chain (SC_HASH), printf if they do.
    - kwq_notifier_init(nf, cpu)/kwq_notify(q, nf)/kwq_notify_cancel:
      pending state under the notifier's fixed (queue, CPU) mutex,
      limit-exempt, cleared at swap-out
      before the handler runs; cancel unlinks and waits for a pass
      holding it (KWQ.md S3).  Test: a notifier signalled 1e6 times from
      two CPUs while the handler counts runs -> runs <= signals, every
      state change observed, zero rejects, `coalesced` accounts for the
      difference.
    - Enqueue: lock, limit check -> ENOBUFS (KWQ_LIMIT_NONE skips it),
      append, IDLE->WAKING + wakeup of the class worker on that CPU (one
      hold), unlock.  kwq_enqueue_list as STAILQ_CONCAT.  ENXIO after
      drain began or before activation.  kwq_cpu_for_hash(): hash %
      (mp_maxid + 1), offline id -> caller's CPU; KWQ_CPU_ANY (BULK) picks
      the least loaded CPU in the caller's cache domain; offline/invalid
      cpu arguments map to the caller's CPU.
    - Drain loop v0: no DRR yet - swap list, run handler under
      NET_EPOCH (NET) with THREAD_NO_SLEEPING(), re-check emptiness under
      lock before IDLE (the if_pair protocol verbatim).
    - kwq_drain (deactivate, run/discard remaining on every CPU, wait for
      in-flight passes), kwq_destroy (asserts drained), MOD_UNLOAD
      returns EBUSY while queues exist, joins all workers (taskqueue_free
      as template).
    Exit: pmcstat remote-HITM / L2 writeback counts recorded on the
    Ampere and amd64 for a two-producer, one-consumer kwq_test load as
    the baseline for P1 (KWQ.md S17); kldload/kldunload 1000x in a loop with no queues; create/
    activate/enqueue/drain/destroy 1000x from kwq_test with items
    counted in == items handled; WITNESS clean; no sleeping-in-handler
    path (a deliberate tsleep in a test handler must panic under
    INVARIANTS).

[TODO] P1  DRR in CPU time, quantum, yield (2-3 days)
    Files: kwq_worker.c.
    - Per-CPU ring of active queues per class plus a "new" list: a
      queue going empty->non-empty is served from the new list before
      the ring for one quantum, then joins the ring (fq_codel rule,
      KWQ.md S15); deficit accounting with cpu_ticks() around each pass;
      quantum per class as sysctl (kern.kwq.net.quantum_us=200,
      kern.kwq.bulk.quantum_us=1000); weights 1..8; PARKED state with
      negative deficit; unused deficit capped at one quantum.
    - kwq_budget_left(q) and kwq_requeue(q, head, tail, n) for cooperative
      handlers; requeue PREPENDS to the current CPU's list so FIFO holds
      (test: items enqueued during a pass never overtake requeued ones).
    - End-of-round and tick-guard yield: kern_yield(yield_prio) then
      sched_prio(class), with kern.kwq.<class>.yield_prio RW, default
      PUSER; never PRI_USER (KWQ.md S11 Missing 1: td_user_pri of a
      timeshare-class kthread is recomputed by ULE every tick, so
      PRI_USER flips between yielding to nobody and yielding whole
      slices to CPU-bound users).  Implement the CPU-share cap as the
      Mogul feedback: per-worker
      busy fraction over a 10 ms window; above kern.kwq.<class>.cap_pct
      (default 90) with sched_runnable() true -> pause_sbt(cap_sleep_us,
      C_PREL(1)) instead of the plain yield.  Both knobs RW.
    Exit: kwq_test "fairness": two NET queues, handlers burning 50 us
    and 500 us per item, saturating one CPU -> cycles within 5 % at equal
    weight, 2:1 within 10 % at weights 2:1.  "latency": oldest-item age
    at pass start never exceeds 2 x quantum x active queues for a
    backlogged queue, and 2 x quantum regardless of active count for a
    queue that was empty (the new-list rule).  "yield":
    a callout at 1 kHz on the saturated CPU keeps its rate within 1 %;
    with the default yield_prio and the cap off, a CPU-bound user process
    bound to that CPU gets ~0 % of it (proves the yield is deterministic;
    compare the same test with kern_yield(PRI_USER) in kwq_test, which
    must show the regime flip after a few seconds of saturation); with
    cap enabled it gets >= (100 - cap) % (measured with ps -o cputime);
    with yield_prio=223 it gets whole slices and maxlat_ns shows it.

kwq_test scenarios (what each proves)
-------------------------------------

  lifecycle   create/activate/enqueue/drain/destroy in a loop; module
              load/unload with live queues refused (EBUSY); no leaks
              (vmstat -m kwq stable).
  fairness    two queues, unequal per-item cost, one saturated CPU;
              cycles ratio == weight ratio within 5-10 %.
  latency     oldest-item age at pass start bounded by quantum x active
              queues (read from kwq:::pass-start via a dtrace -c wrapper
              or from the queue's maxlat_ns counter).
  yield       callout rate and CPU-bound user process share under saturation.
  drain       no item lost or run twice across 100 activate/drain cycles
              under load (each item carries a sequence number and a
              seen-bit checked by the handler).
  reject      bound reached -> ENOBUFS, rejected counter == caller count.
  steal       BULK KWQ_F_STEALABLE: items enqueued on CPU 0 handled on
              CPUs sharing its cache domain first (kwq:::steal args).
  scatter     N chunks, exactly one completion, after all handlers ran.
  requeue     items enqueued during a pass never overtake items the handler
              handed back with kwq_requeue (per-CPU FIFO under budget
              exhaustion).
  steering    kwq_cpu_for_hash maps equal hashes to equal CPUs, never to
              an offline one, and matches inp_flowid % (mp_maxid + 1).
  unbounded   a KWQ_LIMIT_NONE queue never rejects and maxdepth tracks the
              high-water mark; the same load on a limited queue rejects.
  reserve     (P7) a KWQ_F_RESERVE queue progresses while all unreserved
              BLOCKING workers are blocked.
  notifier    (P7) one notifier per CPU over a client-owned list: zero
              rejects under a request flood, all requests completed.
  sleep       a handler that sleeps panics with the expected message
              (INVARIANTS kernel in a VM only).

Examples (kwq/examples/)
------------------------

deferred.c - the minimal client, the shape every taskqueue client migrates to:

    struct ex_work { struct kwq_item item; int arg; };
    static struct kwq *exq;

    static void
    ex_handler(struct kwq *q, struct kwq_item *head, int n, void *ctx)
    {
        struct kwq_item *it, *next;
        KWQ_FOREACH_SAFE(it, head, next) {          /* FIFO, we own them */
            struct ex_work *w = __containerof(it, struct ex_work, item);
            do_work(w->arg);                        /* no sleeping: NET/BULK */
            free(w, M_EXAMPLE);
        }
    }

    /* attach (sleepable) */
    exq = kwq_create("example", KWQ_BULK, 0, NULL, ex_handler, NULL);

    /* any non-filter context */
    struct ex_work *w = malloc(sizeof(*w), M_EXAMPLE, M_NOWAIT);
    if (w == NULL) return (ENOMEM);
    w->arg = 42;
    if (kwq_enqueue(exq, curcpu, &w->item) != 0) { free(w, M_EXAMPLE); return (ENOBUFS); }

    /* detach (sleepable) */
    kwq_drain(exq); kwq_destroy(exq);

scatter.c - BULK fan-out with completion (the wg crypto shape):

    static struct kwq *cryptq;   /* KWQ_BULK | KWQ_F_STEALABLE */

    static void
    all_done(void *arg) { struct batch *b = arg; kwq_enqueue(b->deliverq, b->cpu, &b->item); }

    kwq_scatter(cryptq, first_item, nitems, all_done, batch);
    /* each item is encrypted by whichever BULK worker takes it; when the
       last chunk's handler returns, all_done runs once and hands the
       batch to a serial NET queue for in-order delivery */

pair_client.c - the if_pair conversion, as it will be applied in P4:

    /* per pair side, in clone create */
    sc->sc_q = kwq_create(if_name(ifp), KWQ_NET, KWQ_F_INACTIVE | KWQ_F_DISCARD,
                          NULL, pair_handler, sc);
    ... finish attach ...
    kwq_activate(sc->sc_q);

    pair_output():                       /* enqueue to the PEER side's queue */
        error = kwq_enqueue(peer->sc_q, kwq_cpu_for_hash(m->m_pkthdr.flowid), KWQ_MBUF_ITEM(m));
        if (error) { m_freem(m); if_inc_counter(ifp, IFCOUNTER_OQDROPS, 1); }

    pair_handler(q, head, n, ctx):
        for each mbuf m (m_stailqpkt link):
            pair_input(m->m_pkthdr.rcvif, m);           /* in net epoch already */
            if (more && kwq_budget_left(q) == 0) { kwq_requeue(q, rest_head, rest_tail, n_left); return; }

    pair_clone_destroy(): clear IFF_DRV_RUNNING on both sides; NET_EPOCH_WAIT()
        (no producer is past the peer dereference); kwq_drain(sc_q) on both sides
        (KWQ_F_DISCARD: pending mbufs are freed, in-flight passes finish);
        kwq_destroy both; then if_detach.  Same order as today's per-side queues.

Risks and decisions to take early
---------------------------------

- Item type: generic struct kwq_item embedded vs mbuf-native (m_stailqpkt).
  Decision: generic item; KWQ_MBUF_ITEM()/KWQ_ITEM_TO_MBUF() macros map an
  mbuf's m_stailqpkt to a kwq_item so network clients pay no extra field.
  Verify offsets with CTASSERT.
- One queue per pair side (decided): matches the driver's per-side queues,
  lets clone destroy drain exactly the dying side's items (KWQ.md S4 VNET
  contract), and gives per-pair counters.  Cost is O(ncpu) per queue
  (~32 KB on 128 CPUs); a host with thousands of pairs pays tens of MB,
  acceptable.  A shared queue would need a purge-by-predicate operation
  the API deliberately lacks.
- Quantum defaults: measure, do not guess - P1 exit criteria include a
  sweep of 50/100/200/500 us on the Ampere with t_17.
- Scheduler: DRR plus the new-list rule (decided, KWQ.md S15).  If P1's
  maxlat_ns numbers show light queues still starving behind heavy ones,
  swap the ring for virtual time (WF2Q+/EEVDF over cpu_ticks) behind the
  same API and counters; dummynet's dn_sched_qfq.c is the in-tree
  reference.
- The pause_sbt cap adds jitter equal to cap_sleep_us; default off until
  P1 measurements say what it costs at the 479 Gbit/s peak.
- Preload path (kwq_load in loader.conf): test explicitly on the arm64
  VM; the smp_started wait must not deadlock with SI_SUB_TASKQ ordering.
- KBI: kwq.h must not expose struct kwq; only pointers.  MODULE_VERSION
  bumps on any contract change.
